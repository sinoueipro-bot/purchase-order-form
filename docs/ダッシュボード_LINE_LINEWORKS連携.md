# 統合ダッシュボード ＋ LINE / LINE WORKS 連携 セットアップ手順

「9つの確認先を1画面へ」のイメージで、**LINE WORKS・LINE・Chatwork・Gmail・発注システム・広告実績**を
1画面で確認できるダッシュボードを、この発注書フォームのGASプロジェクトに追加しました。

```
LINE WORKS Bot ────┐（メッセージが来るたびWebhookで通知）
LINE公式アカウント ─┴→ GAS doPost → 「受信メッセージログ」シートに蓄積
Chatwork API・Gmail・発注一覧・広告シート → 表示時にその場で集計
                    ↓
        ?page=dashboard の1画面ダッシュボード
        （60秒自動更新・スマホ対応・要対応キーワード検知）
```

---

## なぜこの方式か（LINE WORKS フリープランの工夫）

LINE WORKSで「過去のトーク履歴をAPIで取り出す」機能（監査ログ／トークログエクスポート）は
**有償プラン専用**です。ただし **Bot（チャットボット）の作成とCallback受信はフリープランでも無料**で使えます
（制限はAPIレート60リクエスト/分のみで、受信には実質影響なし）。

そこで本システムは：

1. LINE WORKSに「受信ログBot」を無料で作る
2. 見たいトークルームにBotを**メンバーとして招待**する
3. ルームに流れるメッセージがBotのCallback（Webhook）でGASに届く
4. GASがスプレッドシートに蓄積 → ダッシュボードに表示

という方式にしています。**トレードオフ（重要）**：

- ✅ 無料で運用できる
- ⚠️ **Botを招待した後のメッセージだけ**が蓄積される（過去ログは取れない）
- ⚠️ Botがいないルームのメッセージは取れない（見たいルームには必ずBotを招待する）

LINE（個人向けLINE）も同様に、**LINE公式アカウント（無料）のWebhook**で受信します。
※個人LINE同士の1:1トークをAPIで読む方法は存在しません（規約違反になる非公式手段は使いません）。
　お客様とのやり取りを「公式アカウント宛て」または「公式アカウント入りのグループ」に寄せる運用にしてください。

## Step 0. GAS側の準備（10分）

1. スプレッドシートの「拡張機能 > Apps Script」を開く
2. 最新のコード（`Code.gs` / `Dashboard.gs` / `dashboard.html` / `appsscript.json`）を反映する
   （claspを使っている場合は `clasp push`）
3. エディタで関数 **`setupDashboard`** を選んで実行
   - 初回は権限承認が出ます。**今回からGmail読み取り権限（gmail.readonly）が増えている**ので再承認してください
   - 「受信メッセージログ」「名前対応表」シートが作成され、認証トークンが自動発行されます
4. 「デプロイ > デプロイを管理 > （既存デプロイの）✏️編集 > バージョン：新バージョン」で**再デプロイ**
   - ⚠️「新しいデプロイ」ではなく**既存デプロイの更新**にすると、URLが変わらずフォームもそのまま動きます
5. もう一度 `setupDashboard` を実行し、**ログに表示される3つのURL**を控える：
   - `【1】LINE WORKS Bot の Callback URL`（`...?hook=lineworks&token=～`）
   - `【2】LINE公式アカウントの Webhook URL`（`...?hook=line&token=～`）
   - `【3】ダッシュボード画面URL`（`...?page=dashboard&key=～`）

> 動作確認だけ先にしたい場合：関数 `testInboundWebhook` を実行するとテストメッセージが1件記録され、
> ダッシュボードのタイムラインに表示されます。

## Step 1. LINE WORKS Bot を作る（フリープランOK・15分）

### 1-1. Developer Console でBotを登録
1. https://developers.worksmobile.com/console/ に **LINE WORKSの管理者アカウント**でログイン
2. 左メニュー「**Bot**」→「**登録**」
3. 入力内容：
   - Bot名：`受信ログBot`（何でもOK）
   - 説明：`ダッシュボード連携用`
   - 管理者：自分を選択
4. **Callback URL：「利用する」をON** にして、Step 0で控えた
   `【1】...?hook=lineworks&token=～` のURLを貼り付け
5. 受信メッセージタイプは「テキスト」など**全てにチェック**
6. 「**複数人のトークルームに招待可**」を**ON**（これがOFFだとグループに入れられません）
7. 保存

### 1-2. 管理画面でBotを公開
1. https://admin.worksmobile.com/ （管理者画面）→「サービス」→「**Bot**」
2. 「追加」ボタン → 1-1で作ったBotを選んで追加 → **公開**

### 1-3. トークルームにBotを招待
1. LINE WORKSアプリで、蓄積したいトークルームを開く
2. メンバー追加（招待）画面で、作成した**Botを追加**
3. 誰かがメッセージを送る → スプレッドシート「受信メッセージログ」に行が増えれば成功🎉

> **1:1でBotに直接話しかけた内容**も蓄積されます（例：外出先から「至急 ○○様クレーム対応中」とBotに送ればダッシュボードの要対応に載る、という使い方も可能）。

---

## Step 2. LINE（公式アカウント）を繋ぐ（無料・15分）

1. LINE公式アカウントを未作成なら https://entry.line.biz/ から無料で作成
2. LINE Official Account Manager（ https://manager.line.biz/ ）→ 設定 →「**Messaging API**」→ **利用を有効化**
   （プロバイダー名は会社名などでOK）
3. LINE Developers コンソール（ https://developers.line.biz/console/ ）で該当チャネルを開き：
   - 「Messaging API設定」タブ → **Webhook URL** に Step 0の `【2】...?hook=line&token=～` を設定
   - 「**Webhookの利用**」を**ON**
   - **チャネルアクセストークン（長期）を発行** → コピー
   - 「グループ・複数人トークへの参加を許可する」を**ON**（グループの会話も拾う場合）
4. Official Account Manager の「応答設定」で：
   - 応答メッセージ：**オフ**（自動返信させない）
   - Webhook：**オン**
5. GASの「プロジェクトの設定 > スクリプト プロパティ」に追加（**送信者名・グループ名の自動表示用／推奨**）：
   - プロパティ名：`LINE_CHANNEL_ACCESS_TOKEN` ／ 値：3で発行したトークン
6. 運用への組み込み：
   - お客様には**公式アカウントを友だち追加してもらい、そこへ連絡してもらう**
   - 社内グループ・お客様グループには**公式アカウントを招待**する
   - → 届いたメッセージが「受信メッセージログ」に蓄積されます

> ⚠️ Developersコンソールの「検証」ボタンは、GASのリダイレクト仕様のため**失敗表示になることがあります**。
> 実際にトークでメッセージを送って、シートに記録されるかで確認してください。

---

## Step 3. 名前対応表（LINE WORKSの表示名）

LINE WORKSのWebhookには**ユーザーIDしか入っていない**ため、初回受信時に「名前対応表」シートへ
IDだけの行が自動追記されます。**D列「表示名」に名前（例：眞鍋、福岡店ルーム）を一度入力**すれば、
以降ダッシュボードは名前で表示されます（LINE側はAPIで自動解決されるので基本不要）。

---

## Step 4. Chatwork を繋ぐ（任意・5分）

1. Chatworkの「サービス連携 > **API Token**」でトークンを発行
   （組織の管理者がAPI利用を許可している必要があります）
2. スクリプトプロパティに追加：
   - プロパティ名：`CHATWORK_API_TOKEN` ／ 値：発行したトークン
3. ダッシュボードに「未読・TO/返信・マイタスク・未読が多いルームTOP」が表示されます

※Chatworkは未読数をAPIでいつでも取れるため、Webhook蓄積は不要です。

---

## Step 5. 広告サマリー（任意）

広告実績をまとめているスプレッドシート（例：デイリーレポートの集計シート）があれば：

- `ADS_SPREADSHEET_ID`：そのスプレッドシートのID（URLの `/d/` と `/edit` の間の文字列）
- `ADS_SHEET_NAME`：シート名（省略時は先頭シート）

をスクリプトプロパティに設定すると、**直近5行**がダッシュボードに表示されます。

---

## Step 6. ダッシュボードを開く

- Step 0で控えた `【3】...?page=dashboard&key=～` をブラウザで開く
- スマホなら「ホーム画面に追加」しておくとアプリのように使えます
- 60秒ごとに自動更新。画面右上の「更新」で手動更新も可能

### 要対応キーワード

本文に以下が含まれると**赤くハイライト＋要対応カード**に載ります（既定値）：

> 至急・大至急・緊急・クレーム・トラブル・故障・ガス漏れ・保安・見積・発注・請求・支払・キャンセル・本日中・今日中・急ぎ

変更したい場合はスクリプトプロパティ `ALERT_KEYWORDS` にカンマ区切りで設定（例：`至急,クレーム,ガス漏れ`）。

## セキュリティ上の注意

- GASのWebhookはHTTPヘッダー署名（X-WORKS-Signature等）を検証できないため、**URL内のtokenで認証**しています。
  **Callback/Webhook URLとダッシュボードURLは社外に共有しないでください。**
- 万一URLが漏れた場合：スクリプトプロパティの `WEBHOOK_TOKEN` / `DASHBOARD_KEY` を削除 →
  `setupDashboard` を再実行（新トークン発行）→ LINE WORKS / LINE側のURLを新しいものに差し替え。
- 受信メッセージはスプレッドシートに平文で蓄積されます。シートの共有範囲にご注意ください。

## 制約まとめ（できないこと）

| 項目 | 可否 | 補足 |
|---|---|---|
| LINE WORKS：Bot招待後のルームのメッセージ蓄積 | ✅ | フリープランOK |
| LINE WORKS：Bot招待前の過去ログ取得 | ❌ | 監査ログAPIは有償プラン専用 |
| LINE WORKS：Botがいないルームの取得 | ❌ | 見たいルームには必ずBotを招待 |
| LINE：公式アカウント宛てメッセージ・OA入りグループ | ✅ | 無料プランOK（受信は無制限） |
| LINE：個人アカウント同士の1:1トーク | ❌ | 公式APIなし。公式アカウントへの連絡に寄せる運用で代替 |
| Chatwork：未読/メンション/タスク数 | ✅ | APIトークンのみでOK |

## トラブルシューティング

| 症状 | 確認すること |
|---|---|
| メッセージが記録されない | ①「新バージョン」で再デプロイしたか ②URLが `/exec`（`/dev`ではない）か ③URLの `token=` がスクリプトプロパティの `WEBHOOK_TOKEN` と一致するか ④Botがそのルームにいるか ⑤（LINE WORKS）Callback URLが「利用する」になっているか |
| LINE Developersの「検証」が失敗する | GASのリダイレクト仕様によるもの。実メッセージ送信で確認 |
| Gmailカードがエラー | 再デプロイ後にGASエディタで任意の関数（例：`setupDashboard`）を実行し、権限を再承認。それでも駄目なら `appsscript.json` のスコープを `https://mail.google.com/` に変えて再承認 |
| Chatworkカードがエラー | トークンの値、組織側のAPI利用許可を確認 |
| 送信者がIDのまま | 「名前対応表」のD列に表示名を入力（LINE WORKSは仕様上手動） |
| ダッシュボードが「アクセスキーが違います」 | URL末尾の `&key=～` が `DASHBOARD_KEY` と一致しているか |
| 動作テストしたい | GASエディタで `testInboundWebhook` を実行 → タイムラインに出るか確認 |

## 運用のヒント

- 朝イチはダッシュボードの**要対応カード**から確認（Chatwork/メールも未読数で一目）
- 「受信メッセージログ」シートはそのままClaude（chatwork-syncスキル等）に読ませて
  **朝のブリーフィング材料**にもできます（LINE WORKS・LINE分も含めた横断要約が可能に）
- ログは直近5,000行を自動保持（古い行は自動削除）。残したい場合は定期的に複製を
